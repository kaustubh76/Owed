2. Promise lifecycle (every transition is a ledger event)

stateDiagram-v2
    [*] --> Captured : promise found in receipt / confirmation / ETA
    Captured --> Watching : window or deadline known
    Watching --> Kept : fulfilment evidence inside window
    Watching --> Suspected : deadline passed, coverage below threshold
    Watching --> Breached : breach evidence, confidence above threshold
    Suspected --> Breached : more evidence
    Suspected --> Kept : late fulfilment evidence
    Breached --> Filed : user confirms (elicitation)
    Filed --> Negotiating : merchant agent responds
    Negotiating --> Settled : offer accepted
    Negotiating --> Escalated : rounds exhausted / stonewall
    Escalated --> Settled : human-route resolved
    Escalated --> WrittenOff : user declines
    Settled --> Recovered : credit or refund observed
    Kept --> [*]
    Recovered --> [*]
    WrittenOff --> [*]

4. Recourse protocol (open, MCP-shaped)

flowchart LR
    C[CLAIM
promise · evidence_pack · policy_ref · ask] --> O[OFFER
amount · form · terms]
    O -->|below reservation| K[COUNTER
amount · policy_clause · evidence_ids]
    K --> O
    O -->|at or above reservation| S[SETTLE
amount · form · reference]
    O -->|rounds exhausted| D[DECLINE
reason · escalation_route]
    K -->|rounds exhausted| D
    D --> E[Escalated → human route]
    S --> R[Recovered when credit observed]

Rules: max 3 rounds by default · every message carries the claim id · evidence referenced, never re-sent · a DECLINE must carry a human escalation route. Negotiator: reservation value from the policy library, concession schedule by merchant type.
